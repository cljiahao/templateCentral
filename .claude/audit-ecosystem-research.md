## Loop engineering — community/team practice

**CONSENSUS** — ≥3 independent credible sources (becomes Step 3H check):
- Multiple independent exit mechanisms: goal verifier + hard iteration cap + token/cost budget. Any one tripping stops the loop.
- Trust deterministic verifier (test pass/fail, linter, checksum), never agent self-report for loop termination. Hallucinated success is a known failure mode.
- No-progress detection: exit if output state unchanged across iterations.
- Circuit breakers: retry limits on individual tool calls.
- Human-in-the-loop checkpoints required for irreversible actions (deploy, send message, delete data).
- Define termination criteria before the loop starts using verifiable automated checks, not improvised mid-run.

**RECOMMENDED** — team/AAIF guidance:
- Token/cost budget as a hard spending limit per run, built in from day one.
- Start with the simplest loop that could work; add complexity only when there is measurable improvement.

**EMERGING** — single credible source (track only):
- Scheduled self-prompting via `asyncRewake` or cron hooks for polling/monitoring loops.
- Loop goal formulation: checkable goals ("make tests pass") vs uncheckable goals ("improve code") — avoid the latter as the loop has no verifiable stop condition.

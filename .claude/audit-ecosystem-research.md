## Loop engineering — community/team practice

**CONSENSUS** (≥3 independent credible sources — becomes Step 3H check):
- Multiple independent exit mechanisms required: goal verifier + hard iteration cap + token/cost budget. Any one tripping stops the loop.
- Trust deterministic verifier (test pass/fail, linter, checksum), never agent self-report. Hallucinated success is a known failure mode.
- No-progress detection: exit if output state unchanged across iterations.
- Circuit breakers: retry limits on individual tool calls.
- Human-in-the-loop checkpoints for irreversible actions (deploy, send, delete).
- Define termination criteria before the loop starts using verifiable automated checks — not improvised mid-run.
- Context management: compact old steps, prune stale tool output, externalize state, isolate sub-agents so subtasks run in a clean window and return only conclusions.

**RECOMMENDED** (team/AAIF guidance):
- Token/cost budget as a hard spending limit per run, built in from day one. Real-world: Uber capped engineers at $1,500/person/tool/month after burning annual AI budget in four months.
- Start with the simplest loop that could work; add complexity only when there is measurable improvement.
- Checkable goals ("make tests pass") vs uncheckable goals ("improve code") — avoid the latter; loop has no verifiable stop condition.

**EMERGING** (single credible source — track only):
- Scheduled self-prompting via `asyncRewake` or cron hooks for polling/monitoring loops.
